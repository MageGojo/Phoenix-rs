# 视图层国际化（phoenix-view i18n）

`phoenix-view` 的 `i18n` 模块提供**视图层**的多语言能力：进程级翻译目录 +
`Accept-Language` 协商 + 把结果注入 `PageEnvelope`，让前端拿到当前 locale 与该
locale 的翻译子集。它是 `phoenix-validation` 消息目录（见 [VALIDATION.md](VALIDATION.md)）
在渲染侧的姊妹件：**两套心智一致**（按 locale 注册、`{name}` 占位符模板、英文式回退），
但**注册表各自独立**——校验目录渲染 422 错误消息，视图目录渲染页面/组件文案。

关键区别：校验有一个**进程级 active locale**（`set_locale`）；视图 locale 是
**按请求协商**的（来自 `Accept-Language`），所以视图侧只有一个**默认/回退 locale**
（`set_default_locale`），没有全局 active。

## 1. 翻译目录

按 locale 存 `key -> 模板`，模板用 `{name}` 占位符。全部从内存注册，进程级
（读多写一次，建议只在启动阶段写入）。

```rust
use phoenix_view::i18n;

// 主入口：合并注册若干 key -> 模板（可多次调用，同 locale 累加/覆盖）
i18n::register_translations("en", [
    ("greeting", "Hello, {name}!"),
    ("bye", "Goodbye"),
]);
i18n::register_translations("zh-CN", [
    ("greeting", "你好，{name}！"),
]);

// 单条注册/覆盖
i18n::register_translation("zh-CN", "bye", "再见");

// 或用 Translations 目录对象整体替换某 locale
use phoenix_view::Translations;
i18n::register_locale(
    "zh-TW",
    Translations::new()
        .entry("greeting", "你好，{name}！")
        .entry("bye", "再見"),
);
```

渲染单条文案（服务端插值）：

```rust
// 解析顺序：请求 locale -> 默认 locale -> key 原文
assert_eq!(i18n::translate("zh-CN", "greeting", &[("name", "Ada")]), "你好，Ada！");
assert_eq!(i18n::translate("zh-CN", "bye", &[]), "再见");
// zh-CN 缺失时回退默认 locale（en）；两处都缺失时回退 key 本身：
assert_eq!(i18n::translate("zh-CN", "unknown", &[]), "unknown");
```

默认 locale 缺省为 `"en"`（常量 `i18n::DEFAULT_LOCALE`），可改：

```rust
i18n::set_default_locale("zh-CN"); // 影响 translate / translation_catalog 的回退基准
let _ = i18n::default_locale();    // 读回当前默认 locale
```

`translation_catalog(locale)` 返回**默认 locale 打底、请求 locale 覆盖**后的完整
map——这是注入信封给前端的那份数据，保证前端 key 覆盖完整且能优雅回退：

```rust
let catalog = i18n::translation_catalog("zh-CN"); // BTreeMap<String, String>
```

## 2. Accept-Language 协商

纯函数 `negotiate_locale`：按 `q` 值排序（默认 `1.0`，`q=0` 视为拒绝），对
`available` 依次做「精确匹配（大小写不敏感）→ 主语言子标签匹配」，命中返回
`available` 中的原始大小写，全不中返回 `default`。通配 `*` 选 `default`。

```rust
use phoenix_view::negotiate_locale;

// q 值排序：en 的 q 更高，胜出
assert_eq!(negotiate_locale("zh-CN;q=0.8, en;q=0.9", &["en", "zh-CN"], "en"), "en");
// 精确匹配
assert_eq!(negotiate_locale("zh-CN", &["en", "zh-CN"], "en"), "zh-CN");
// 主子标签匹配（双向）：zh <-> zh-CN、en-US -> en
assert_eq!(negotiate_locale("zh", &["en", "zh-CN"], "en"), "zh-CN");
assert_eq!(negotiate_locale("en-US", &["en", "zh-CN"], "zh-CN"), "en");
// 相同 q 保持 header 原始顺序；未命中/空 header 回退 default
assert_eq!(negotiate_locale("fr, de", &["en", "zh-CN"], "en"), "en");
```

从**现有 Request headers** 读取（用 `phoenix-http` 的只读 `HeaderMap` API，
不修改 `phoenix-http`）：

```rust
use phoenix_view::negotiate_locale_from_headers;

let locale = negotiate_locale_from_headers(request.headers(), &["en", "zh-CN"], "en");
```

## 3. 控制器 / 视图用法

在控制器里把协商结果挂到 `Page` 上。`Page::negotiate_locale` 是
「读 header + 协商 + 注入」的一步封装：

```rust
use phoenix_view::Page;

pub fn show(request: &Request) -> Page {
    Page::new("dashboard/show", props)
        // 读 Accept-Language，在 available 中挑最优，回退 "en"
        .negotiate_locale(request, &["en", "zh-CN"], "en")
}
```

若 locale 由别处得到（用户偏好、URL 段、Cookie……），用 `Page::locale` 直接注入：

```rust
let locale = i18n::negotiate_locale(accept_language, &["en", "zh-CN"], "en");
let page = Page::new("dashboard/show", props).locale(locale);
```

`Page::locale(locale)` 会：

1. 把 `locale` 写入 `PageEnvelope.locale`；
2. 用 `translation_catalog(locale)` 填充 `PageEnvelope.translations`；
3. 该 locale 同时驱动 `<html lang>` 与 SSR renderer 的 `RenderContext.locale`
   （renderer protocol v2 已透传 `locale`）。

## 4. PageEnvelope 新增字段（前后端契约）

`PageEnvelope` 是前后端契约，新增字段**向后兼容**（serde `default` / 空则不序列化），
既不破坏既有测试，也不破坏 `packages/phoenix-react` 的 `protocol.ts`：

| 字段 | 类型 | JSON 形状 | 说明 |
| --- | --- | --- | --- |
| `locale` | `String` | `"locale": "zh-CN"` | 协商出的文档 locale；缺省 `"en"`（`#[serde(default)]`），恒序列化 |
| `translations` | `BTreeMap<String,String>` | `"translations": { "greeting": "你好，{name}！" }` | 该 locale 的 `key -> 模板`（默认 locale 打底）；**为空时不出现在 JSON**（`skip_serializing_if`） |

```json
{
  "protocol": 1,
  "render_mode": "islands",
  "page": "dashboard/show",
  "props": {},
  "locale": "zh-CN",
  "translations": { "greeting": "你好，{name}！" },
  "routes": {},
  "islands": []
}
```

未调用 `.locale()` / `.negotiate_locale()` 的页面输出与旧版本兼容：`locale` 为
`"en"`，`translations` 缺省为空（不出现在 JSON），`<html>` 上补一个
`lang="en"`。应用自定义 `DocumentTemplate` 若显式设置了 `.language(...)`，则
**模板优先**，不再由 locale 注入 `lang`。

## 5. 前端如何取

`translations` 装的是**模板**（含 `{name}` 占位符），前端可在客户端做插值，从而
支持带动态参数的文案。React 侧从 `PageEnvelope` 读取 `locale` 与 `translations`
并暴露 `useTranslations` hook（详见 [REACT.md](REACT.md)，前端接入待补）。约定：

- `t(key, params)` 按 `translations[key]` 取模板并替换 `{name}` 占位符；
- 缺 key 回退 key 原文（与服务端 `translate` 一致）；
- `locale` 供 `<html lang>`、`Intl.*` 格式化与语言切换使用。

## 6. 与校验 i18n 的关系

| 维度 | 校验（phoenix-validation） | 视图（phoenix-view i18n） |
| --- | --- | --- |
| 目录对象 | `Messages` | `Translations` |
| 注册整套 | `register_locale(locale, Messages)` | `register_locale(locale, Translations)` |
| 合并注册 | `override_message` / `register_field_names` | `register_translations` / `register_translation` |
| 渲染 | `rule_message(rule, field, params)` | `translate(locale, key, params)` |
| locale 选择 | 进程级 active：`set_locale` | 按请求协商 + 默认：`negotiate_locale` / `set_default_locale` |
| 占位符 | `{name}`（如 `{field}` / `{min}`） | `{name}` |
| 回退 | active locale -> en -> 内置英文 | 请求 locale -> 默认 locale -> key 原文 |

两者**注册表彼此独立**：校验管 422 错误文案，视图管页面文案；改一个不影响另一个。
建议启动时一并配置，让同一次请求的错误消息与页面文案使用一致的语言（例如按
`negotiate_locale` 的结果同步调用 `phoenix_validation::set_locale`）。

## 7. API 汇总

翻译目录：`Translations` / `register_translations` / `register_translation` /
`register_locale` / `translate` / `translation_catalog` / `set_default_locale` /
`default_locale` / `available_locales` / `DEFAULT_LOCALE`。

协商：`negotiate_locale` / `negotiate_locale_from_headers`。

页面注入：`Page::locale` / `Page::negotiate_locale`；信封字段
`PageEnvelope.locale` / `PageEnvelope.translations`。

全部位于 `phoenix_view::i18n`，主要项也在 crate 根重导出
（`phoenix_view::{negotiate_locale, translate, register_translations, Translations, ...}`）。

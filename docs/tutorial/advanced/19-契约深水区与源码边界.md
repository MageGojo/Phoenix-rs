# 19 · 契约深水区与源码边界

← [18 生产与多库](./18-生产与多库.md) · 下一章 → [20 高级验收](./20-高级验收.md)

## 目标

知道深入问题时该读哪些文档与 crate，避免在错误层打补丁。

## 必做

### 1. 契约深挖（阅读）

精读 `docs/CONTRACTS.md` 中关于：

- input / output / page  
- Serde rename 与字段碰撞  
- `contractHash` 兼容策略  

在笔记里用你的 Note 资源举一个「改名字段会怎样」的例子。

### 2. 页面协议（阅读）

浏览 `docs/RENDERING.md` / React DX 文档中 PageEnvelope、局部导航、flash/errors 的语义。  
不必一次实现全部钩子；知道「协议在 Rust 与 `@apizero/react` 两侧对齐」。

### 3. Crate 地图（浏览）

在框架仓库 `crates/` 建立索引意识（名字随版本微调）：

| 区域 | 代表 crate |
| --- | --- |
| HTTP / 路由 | `phoenix-http`、`phoenix-routing` |
| 运行时组装 | `phoenix-runtime`、门面 `phoenix`（包名 `phoenixrs`） |
| 校验 / 安全 | `phoenix-validation`、`phoenix-security` |
| 数据库 | `phoenix-database` |
| 发版 | `phoenix-release` |
| CLI | `px-cli`（二进制 `px`） |
| 前端包 | `packages/phoenix-react`、`phoenix-vite`、`phoenix-react-ssr` |

遇到 bug：先判断在应用层还是框架层，再决定最小复现。

### 4. 决策与进度

知道 `docs/DECISIONS.md`、`docs/PROGRESS.md` 的用途：查「为什么这样设计」和「当前做到哪」。

## 验收

- [ ] 能指出改契约字段的正确步骤  
- [ ] 能说出至少 4 个核心 crate 的职责  
- [ ] 知道 ISSUE/深入前先查 DECISIONS

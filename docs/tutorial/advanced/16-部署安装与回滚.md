# 16 · 部署安装与回滚

← [15 发版流水线](./15-发版流水线.md) · 下一章 → [17 Plugin 扩展](./17-Plugin扩展.md)

## 目标

在本地模拟部署根，完成安装 → 更新 → 回滚，并理解 `--restart-cmd`。

## 必做

### 1. 准备部署根

```bash
export PHOENIX_DEPLOY_ROOT=/tmp/learn-phoenix-deploy
mkdir -p "$PHOENIX_DEPLOY_ROOT/shared/storage"
cp .env.example "$PHOENIX_DEPLOY_ROOT/shared/.env"
# 编辑 shared/.env：APP_ENV、APP_ADDR、ALLOWED_HOSTS 等
```

布局预期：

```text
$PHOENIX_DEPLOY_ROOT/
  releases/<ver>/
  current -> releases/<ver>
  shared/.env
  shared/storage/
```

### 2. 安装 0.1.0

```bash
px release:install \
  --tarball dist/releases/0.1.0/*.tar.gz \
  --version 0.1.0 \
  --restart-cmd 'echo restarted'   # Linux 生产可换成 systemctl restart <unit>
```

验收输出含 `SWITCHED=true`；有迁移时 `MIGRATED=true`。

```bash
px release:status --deploy-root "$PHOENIX_DEPLOY_ROOT"
```

### 3. 做一版更新（0.1.1）

1. 改业务或加迁移（例如给 notes 加列）  
2. `px release --version 0.1.1 --tarball`  
3. 再次 `release:install`（换 tarball 与 version，带 `--restart-cmd`）  
4. 确认：`current=0.1.1`，`shared/storage` 里旧数据仍在，新迁移已应用  

### 4. 回滚

```bash
px release:rollback --steps 1 --restart-cmd 'echo restarted'
px release:status
```

记住：默认**不会**自动 `migrate down`（生产 forward-only）。

### 5. Islands / SSR 注意

制品不含 `node_modules`。生产需自行提供 Node 与 `react` / `react-dom`（或等价），使 `public/ssr/renderer.js` 可解析。SPA 生产通常不需要长期 Node renderer。

## 讲解

| 结果 | 含义 |
| --- | --- |
| 校验/迁移失败 | **不**切换 `current` |
| 重启失败 | 代码可能已切换 → 人工 rollback |
| `--restart-cmd` | install 仅在显式传入时执行 |

macOS 无 systemd：用脚本模拟 `systemctl` 即可练流程。

## 验收

- [ ] 完成至少一次 install + 一次升版 install  
- [ ] 完成一次 rollback  
- [ ] 能口述 `releases` / `current` / `shared` 职责

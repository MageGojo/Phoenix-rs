# 15 · 发版流水线

← [14 中级验收](../intermediate/14-中级验收.md) · 下一章 → [16 部署安装与回滚](./16-部署安装与回滚.md)

## 目标

在开发机打出带版本的 release 制品（含二进制与 migrations）。

## 必做

### 1. 阅读专章

通读 `docs/RELEASE_PIPELINE.md`（命令表 + 制品内容 + 不含什么）。

### 2. 打第一包

在练习应用根：

```bash
px release --version 0.1.0 --tarball
```

观察输出中的 `STAGING`、`TARBALL`、`SHA256`。

### 3. 检查 staging

```bash
ls dist/releases/0.1.0/staging/bin
cat dist/releases/0.1.0/staging/manifest.toml
```

确认：

- [ ] `bin/<app>` 存在  
- [ ] 有 DB 时有 `bin/phoenix-manage`  
- [ ] `[migrations] included = true`（有迁移时）  
- [ ] 有 `public/assets`、`config`、`manifest.toml`  
- [ ] **没有** `.env`、`node_modules`、`target`

### 4. （可选）staging 烟测

```bash
STAGING=dist/releases/0.1.0/staging
mkdir -p "$STAGING/storage"
# Islands：需能解析 react（例如把开发机 node_modules 链到 $STAGING/node_modules）
(cd "$STAGING" && ./bin/phoenix-manage migrate)
# (cd "$STAGING" && ./bin/<app> serve)  # 注意端口与 .env
```

## 讲解

```text
开发机/CI:  px release --tarball
     ↓  scp/rsync/对象存储（框架不管上传）
服务器:    px release:install …
```

服务器**不需要** Rust 工具链来跑业务；需要 `px`（若走官方 install）以及运行二进制 +（Islands/SSR）Node。

## 验收

- [ ] 得到 `.tar.gz` 与可读的 `manifest.toml`  
- [ ] 能说明制品内有什么、故意不包含什么

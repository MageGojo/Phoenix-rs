# 18 · 生产与多库

← [17 Plugin 扩展](./17-Plugin扩展.md) · 下一章 → [19 契约深水区与源码边界](./19-契约深水区与源码边界.md)

## 目标

掌握上线前配置纪律，以及切换 PostgreSQL/MySQL 时的 feature 对齐。

## 必做

### 1. 生产配置清单

对照 `docs/CONFIG.md` / `SECURITY`，为练习应用写一份「若上线」清单（可先不真上）：

- [ ] `APP_ENV=production`  
- [ ] `APP_URL` 为 https 公网 URL（若适用）  
- [ ] `ALLOWED_HOSTS` 收紧  
- [ ] 密钥仅在 `shared/.env`，不进 git、不进 tarball  
- [ ] Rate limit / Trusted proxies 按部署拓扑设置  
- [ ] 进程管理：systemd（或等价）+ `release:install --restart-cmd`  

### 2. 多库对齐规则（纸面演练即可）

假设要从 SQLite 换到 PostgreSQL：

1. Cargo：启用 `pgsql` feature，去掉或不默认 `sqlite`（按你策略）  
2. `config/database.toml`：`default = "pgsql"`，填连接  
3. `.env`：`DB_PASSWORD` 等  
4. 迁移 SQL 方言差异要过一遍  
5. 重新 `px release`（制品链的是新驱动）  

**红线：** `database.toml` 的 default 与已编译 feature 不一致会导致运行期痛苦。

### 3. 迁移纪律

- 上线迁移由 `release:install` 在切 `current` 前执行  
- 回滚代码 ≠ 回滚 schema（默认 forward-only）  
- 破坏性改表要有扩展计划（兼容旧二进制读库）

## 讲解

Release profile 脚手架偏向体积（`opt-level = "z"`、LTO、strip），并保留 `panic = "unwind"`。  
TLS、指标、Redis 等见专章；按需开启，不要「生产包厨房水槽」。

## 验收

- [ ] 写出你的生产清单（笔记或 PR 描述均可）  
- [ ] 能陈述换 PG/MySQL 的五步对齐  
- [ ] 理解「代码回滚不自动 down 迁移」

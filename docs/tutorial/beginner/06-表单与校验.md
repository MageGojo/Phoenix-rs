# 06 · 表单与校验

← [05 路由与控制器](./05-路由与控制器.md) · 下一章 → [07 初级验收](./07-初级验收.md)

## 目标

做一个「提交 JSON → 校验 → 成功或 422」的最小 action（可不落库）。

## 必做

### 1. 生成 Request（入参契约）

```bash
px make:request StoreFeedbackRequest
```

编辑生成文件：至少一个字段（如 `message: String`），`Validate` 里使用 `required` / `string` / `max_length` 等规则（参照脚手架或 `docs/REACT_DX_FORMS.md` 示例）。

### 2. 挂 POST action

在路由中增加 POST，并声明 action 类型，例如：

```rust
.post("/feedback", typed(FeedbackController::store))
.name("feedback.store")
.action::<StoreFeedbackRequest, FeedbackResource>()
```

`FeedbackResource` 可用 `px make:resource FeedbackResource` 生成一个简单输出（如 `{ ok: bool, echo: String }`）。控制器 `store` 使用 `Validated<Json<StoreFeedbackRequest>>`，成功返回 201/200 + JSON。

### 3. 前端调用

用 `@apizero/react` 的 `Form` + 生成的 action（CSRF、422 回填、防重复提交都是自动的）：

```tsx
import { Form, FieldError } from "@apizero/react";
import { feedback } from "../generated/routes.js";

<Form action={feedback.store} initialValues={{ message: "" }}>
  {(form) => (
    <>
      <textarea
        value={form.data.message}
        onChange={(e) => form.setField("message", e.target.value)}
      />
      <FieldError errors={form.errors} name="message" />
      <button disabled={form.processing}>提交</button>
    </>
  )}
</Form>
```

想直接测裸 API 也可以用 curl，但要自己处理 CSRF（先 GET 任一页面取 `x-csrf-token` 与 cookie，再 POST 带 `X-CSRF-Token` 头）——体会一下框架帮你省了什么。

### 4. 故意触发 422

提交空 `message` 或超长字符串，确认返回校验错误而不是 500。

## 讲解

| 概念 | 作用 |
| --- | --- |
| Request + `Validate` | 入站校验，失败 → 422 |
| Resource | 出站 JSON 形状 |
| `.action::<In, Out>()` | 生成可调用的 TS action |
| CSRF | 脚手架默认开启，不要为省事关掉 |

破坏性变更（DELETE/PUT）后续一律走 typed JSON action，不要用 method-spoofing 链接。

## 验收

- [ ] 合法提交返回成功 JSON
- [ ] 非法提交返回 422（或框架约定的校验响应）
- [ ] 未关闭 CSRF / Session 中间件

# 05 · 路由与控制器

← [04 页面与 Props](./04-页面与Props.md) · 下一章 → [06 表单与校验](./06-表单与校验.md)

## 目标

用 CLI 增加页面路由，理解「命名路由」习惯。

## 必做

### 1. 用生成器加控制器与页面（推荐）

```bash
px make:page about/index
px make:controller AboutController --route
```

若生成器选项与版本略有差异：以 `px make:controller --help` / `px make:page --help` 为准。  
目标是得到：

- `app/controllers/about_controller.rs`（或等价）
- `views/pages/about/…`
- `routes/` 下挂上命名路由（如 `about` → GET `/about`）

### 2. 手动核对命名

在 `routes/*.rs` 中确认类似：

```rust
.get("/about", AboutController::index)
.name("about")
```

React / 服务端都应优先用名字，而不是散落硬编码 URL（页面协议表单有例外，中级再讲）。

### 3. 实现 `index`

返回一个简单 `Page`（可暂用少量 Props，或复用字符串页）。用浏览器打开 `/about`。

### 4. 从首页链过去

在 `home.tsx` 增加链接。推荐直接用生成的路由构造器（不硬编码 URL）：

```tsx
import { Link } from "@apizero/react";
import { about } from "../generated/routes.js";

<Link href={about()}>关于</Link>
```

带参数的路由同理：`users.show({ id: 3 })` → `/users/3`（详见 `docs/REACT.md` §3）。

## 讲解

- `phoenix::mount_routes!()` 会收集 `routes/*.rs`。
- 资源型七条路由用 `px make:model X --all` 或 resource 控制器，放在中级做。
- 冲突的路径或重名会在编译期/启动期失败——这是特性，不是噪音。
- **连写不是强制的**。`Routes` 是消费型 builder，`.name()` / `.action()` / `.middleware()` 修饰的是「最近声明的那条路由」，所以它们必须紧跟对应的 `.get`/`.post`——这是设计，不是笔误。但整个文件不必一条链写到底：可以 `let routes = routes.get(...)...;` 分段重新赋值，或按业务拆成多个函数再 `.merge(...)` / `.group(...)` 组合。路由多了就拆文件，`mount_routes!()` 会收集。

## 验收

- [ ] `/about`（或你选的路径）返回 200 且是你的内容
- [ ] 路由带 `.name(...)`

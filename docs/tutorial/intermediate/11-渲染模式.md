# 11 · 渲染模式

← [10 契约与生成物](./10-契约与生成物.md) · 下一章 → [12 安全与中间件](./12-安全与中间件.md)

## 目标

搞清 SPA / Islands / SSR 共享什么、差在哪；**只改 Page 链上的模式**，不重写后端。

## 必做

### 1. 阅读对照

读 `docs/RENDERING.md` 的概述表（共享页面协议、契约、路由）。  
在控制器里找到：

```rust
.islands()  // 或 .spa() / .ssr()
```

### 2. 受控实验（同一页面）

选 **Home 或 Notes 其中一个页面**：

1. 记下当前模式与响应头 `x-phoenix-render-mode`（若有）。  
2. 改为另一种模式，保存，硬刷新。  
3. 观察：HTML 完整度、是否依赖 Node renderer、浏览器行为差异。  
4. **改回**你练习应用的主模式（建议 Islands，与脚手架默认一致）。

不要同时改多个页面到不同模式「玩飞」——先建立单一默认。

### 3. Islands 组件（若主模式为 Islands）

```bash
px make:island Counter
```

在某一页面放入带 `client:load` 的岛屿（语法以 `@apizero` / 文档为准），确认水合后可交互。

## 讲解

| 模式 | 开发期 | 生产要点 |
| --- | --- | --- |
| SPA | Vite | 可不依赖长期 Node renderer |
| Islands | Vite + renderer | 生产需 Node 能解析 renderer 依赖（如 react） |
| SSR | Vite + renderer | 生产同样需要 renderer |

三者共享：路由、控制器、校验、契约、页面协议局部导航语义（细节见专章）。

## 验收

- [ ] 能说明三种模式各自何时需要 Node renderer  
- [ ] 练习应用有一个明确的默认模式  
- [ ] 实验后已改回默认，应用仍正常

# 12 · 安全与中间件

← [11 渲染模式](./11-渲染模式.md) · 下一章 → [13 Feature 与测试](./13-Feature与测试.md)

## 目标

认识脚手架默认中间件链，学会在保留安全默认的前提下扩展。

## 必做

### 1. 阅读 `application` / `routes` 中间件顺序

在 `src/lib.rs` 标出（名称以项目为准）：

- TrustedProxies、RequestId、AccessLog  
- ServeProductionAssets（有 manifest 时）  
- HostAllowlist、RateLimit  
- CSP（NonceSecurityPolicy）  
- Session、Csrf  
- State：Config / Assets / Renderer / Database  

### 2. 验证 CSRF 仍有效

对写操作不带 CSRF 头：应失败（403 或框架约定）。  
带齐 cookie + `X-CSRF-Token`：应成功。

### 3. 添加一个无害中间件（可选）

```bash
px make:middleware RequestTimerMiddleware
```

挂到链上（位置要合理：勿放在破坏 Session/CSRF 语义之处）。用日志或响应头证明执行到了。

### 4. 配置核对

- `ALLOWED_HOSTS`、`TRUSTED_PROXIES`  
- `RATE_LIMIT_*`（本地压测可临时调高，勿在教程里学「关掉限流当常态」）

## 讲解

安全默认是产品的一部分：为图省事删除 CSRF/CSP/HostAllowlist，等于学歪。  
生产 `APP_ENV=production` 时配置校验更严——高级章节再展开。

## 验收

- [ ] 能按顺序列出默认中间件职责  
- [ ] CSRF 正反用例都试过  
- [ ] 未删除 Session/CSRF/CSP

# 10 · 契约与生成物

← [09 模型、迁移与 CRUD](./09-模型迁移与CRUD.md) · 下一章 → [11 渲染模式](./11-渲染模式.md)

## 目标

理解「Rust 唯一来源 → TS 生成物」，并在前端正确使用。

## 必做

### 1. 阅读生成物（只读）

打开并浏览：

- `views/generated/contracts.ts`：`NoteResource`、`StoreNoteRequest`、`NotesIndexProps`、`contractHash`
- `views/generated/routes.ts`：命名路由表与 action 辅助（若有）

### 2. 做一次字段变更实验

1. 在 Rust `NoteResource` / Props **增加**一个字段（例如后续才用的可选字段，或先加 `body` 并同步模型/迁移——若加列，先写迁移再改模型）。  
2. 保存，执行 `npm run types` 或 `px make:*` 触发的刷新 / `cargo check` 后的生成流程（以项目脚本为准）。  
3. 确认 `contracts.ts` 出现新字段。  
4. **故意**手改 `contracts.ts` 后立刻还原，并记住：正确做法永远是改 Rust。

### 3. 前端使用命名产物

在 `views/pages/notes/index.tsx`：

- Props 类型从 `generated/contracts` 导入  
- 链接/跳转优先用生成 routes（若 API 已生成 helper）；提交用生成 action / Form  

## 讲解

| 属性 | 约定 |
| --- | --- |
| 来源 | `#[phoenix::contract(...)]` 在 Rust |
| 方向 | input（Request）/ output（Resource）/ page props |
| 兼容 | `contractHash`；前后端不一致会出问题 |
| 禁忌 | 手改 generated；TS 独有字段无 Rust 来源 |

## 验收

- [ ] 能指着文件说明：谁生成谁、谁是源  
- [ ] 前端类型来自 generated  
- [ ] 完成一次「改 Rust → 生成物更新」
